## 一、项目概述

SpeakBuddy 是一个浏览器端的英语口语练习工具。用户可以选择对话场景（面试 / 点餐 / 会议），通过按住说话与 AI 进行实时语音对话。系统会提供发音评测、语法纠错和课后总结。

## 二、技术栈

### 前端
- React 18 + TypeScript + Vite
- Tailwind CSS (通过 @tailwindcss/vite 插件)
- shadcn/ui 组件（使用默认样式，可从 npx shadcn@latest add button 等引入）
- 状态管理：Zustand
- 音频采集：Web Audio API + MediaRecorder API（opus 编码，每 200ms 发送 chunk）
- 语音活动检测：使用 @ricky0123/vad-web 的轻量 VAD（可选，后续集成，本次先做手动按住说话）
- WebSocket 通信：原生 WebSocket

### 后端
- 运行时：Node.js (使用 Bun 或 Node，推荐 Bun)
- 框架：Hono，集成 WebSocket 支持 (@hono/node-server 和 createNodeWebSocket)
- API 集成：
  - Deepgram 实时流式语音识别（@deepgram/sdk，使用 `listen.live`）
  - OpenAI GPT-4o-mini 进行对话生成和语法纠错（openai 官方 SDK）
  - OpenAI TTS（tts-1 模型）生成语音回复，返回 mp3 二进制
- 暂时不集成数据库，对话历史保存在内存中即可。

## 四、核心功能与实现细节

### 4.1 场景选择
- 三个场景：面试 (interview)、点餐 (ordering)、会议 (meeting)。
- 点击场景按钮时，通过 WebSocket 发送 `{ type: 'set_scenario', scenario: '...' }`。
- 后端收到后更新对话角色提示词，并清空历史。

### 4.2 实时语音对话流程
1. 用户按住 RecordButton 开始录音，使用 MediaRecorder（mimeType: 'audio/webm;codecs=opus'），每 200ms 触发 ondataavailable，将 Blob 转为 ArrayBuffer 后通过 WebSocket 发送。
2. 后端收到二进制音频数据，直接喂给 Deepgram Live 连接。
3. Deepgram 返回最终识别文本后，后端执行以下操作（并行）：
   - 调用 OpenAI GPT-4o-mini 生成对话回复（使用对应的场景 system prompt）。
   - 将用户文本和 AI 回复文本通过 WebSocket JSON 消息发送给前端。
   - 调用 OpenAI TTS 生成语音，将音频二进制数据直接发送给前端。
4. 前端接收到用户文本和 AI 文本后，添加消息到聊天列表；接收到音频数据时，为最近一条 AI 消息创建播放 URL。

### 4.3 后端场景 System Prompt
你需要根据场景参数设定 system prompt。以下是三个场景的完整 prompt（请原样使用）：
- **interview**: `You are an experienced HR interviewer at a tech company. You are interviewing a candidate for a software engineer position. Guidelines: - Ask behavioral and technical questions naturally. - React to the candidate's responses with follow-up questions. - Keep the tone professional but friendly. - Limit each response to 2-3 sentences to keep the conversation moving.`
- **ordering**: `You are a friendly waiter at a nice restaurant. Take the customer's order, suggest dishes based on their preferences, and handle any special requests. Use casual, polite English. Keep responses short and natural.`
- **meeting**: `You are a project manager leading a daily standup meeting. Ask each team member (the user) about their progress, any blockers, and plans for the day. Be encouraging and efficient. Keep the tone professional but supportive.`

### 4.4 WebSocket 消息协议
所有文本消息均为 JSON 格式，二进制消息为音频数据。

**前端 → 后端：**
- 设置场景：`{ "type": "set_scenario", "scenario": "interview" }`
- 音频二进制数据（直接发送）

**后端 → 前端：**
- 连接就绪：`{ "type": "ready", "message": "Connected" }`
- 用户识别文本：`{ "type": "user_text", "text": "..." }`
- AI 回复文本：`{ "type": "ai_text", "text": "..." }`
- 场景已设置：`{ "type": "scenario_set", "scenario": "interview" }`
- 二进制：AI 语音回复 (mp3)

### 4.5 前端组件行为
- **App.tsx**：顶部是 ScenarioSelector，中间是聊天消息列表（自动滚动到底部），底部是 RecordButton。
- **ChatBubble.tsx**：接收 role 和 text，用户消息靠右蓝色，AI 消息靠左灰色。如果该消息有 audioUrl，显示一个播放按钮。
- **RecordButton.tsx**：用 onMouseDown/onMouseUp 控制录音，按下时红色缩放动画，显示“●”图标。
- **useWebSocket.ts**：管理 ws 连接，提供 sendAudio 和 setScenario 方法，处理 onmessage 分发。

### 4.6 关键点
- 后端使用 Deepgram 时，需确保传入的正确音频格式。因为 MediaRecorder 输出 webm opus，Deepgram 可以直接识别（可能需要指定编码参数，如果不行，可先不设置，让 Deepgram 自动检测）。
- OpenAI TTS 使用 `tts-1` 模型，语音 `alloy`，输出格式为 mp3。
- 所有 API 密钥放在后端 .env 文件中，前端不可见。
- 项目必须能分别在 backend 和 frontend 目录下执行 `bun install` 和 `bun run dev`（或 npm）后正常运行。
- 请在代码中处理基本异常，如网络断开、API 错误等，控制台输出错误即可。
